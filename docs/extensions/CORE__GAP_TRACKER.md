- Java 的命名实例注册表（`register(String, Model)` / `getRegistered` / `@` 保留字符 / 重注册告警）：Rust `ModelRegistry` 是按实例持有的 provider 列表，无全局命名实例、无解析缓存（架构裁定见 `MODEL__GAP_TRACKER.md` §4.2 #11），宿主侧由 `model_resolver` 承担；引入全局可变命名表与该裁定冲突。
- `contextId@modelId` 复合身份、creation-context 轮换（generation）、`evictResolvedCache*`、显式指纹漂移告警、`cacheId` 的 `#` 校验：全部服务于 creation-context 注册表与解析缓存，Rust 无此二者；`ModelCreationContext.cache_id` 是公开字段且不存在 `#` 命名空间，校验无对象。
- 「多个 SPI provider 同时声明同一 id → 报错」：Rust 的 OpenAI 兼容 provider `supports()` 恒为 `true`（网关/自建端点），任何含两个 provider 的注册表都会被判为歧义，照搬会让 `full_registry()` 的裸名解析全面失败；保留「注册顺序首个匹配」并写入 `ModelProvider` 文档。
- Java 删除 `RuntimeContext.modelId`：Rust 保留该字段（公共 API 兼容），仅新增钉住槽位并文档化优先级。
