# 会话摘要 2026-09-01（ACP 取消支持）

## 目标
实现 ACP `$/cancel_request` 取消支持——`docs/ACP_AGENT__GAP_TRACKER.md` 2.4 中唯一剩余 P1 缺口。

## 诊断结论
- SDK 无需注册 `CancelRequestNotification` 通知 handler：收到 `$/cancel_request` 时 SDK 自动
  更新对应 `Responder` 的 cancellation marker（`Responder::cancellation()` → `RequestCancellation`）。
- 关键约束：长 handler 阻塞 dispatch loop，`$/cancel_request` 永远无法被处理 → 必须 `cx.spawn` 移出。

## 完成修改
- **session.rs**：新增 `run_prompt_cancellable(content, emit, Option<RequestCancellation>)`，
  与 `run_prompt` 共享 `run_prompt_inner`；select 中监听 `cancellation.cancelled()` → `StopReason::Cancelled`。
- **coding_agent.rs**：
  - PromptRequest handler 取 `responder.cancellation()`，`cx.spawn` 中运行 `run_prompt_cancellable`，
    handler 立即返回（dispatch loop 空闲可处理取消通知）。
  - 新增 `run_with_transport`（transport 可注入），`run_stdio` 委托之（测试可注入 Channel）。
- **tests/acp_cancel_test.rs（新）**：进程内 `Channel::duplex` + never-ending model 的取消 e2e。

## 验证

- `cargo build -p agentscope-harness` + `--example acp_harness_agent` 通过。
