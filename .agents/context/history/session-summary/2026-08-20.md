# 会话摘要 2026-08-20

## 目标
实现功能完整的 ACP 协议 CodingAgent（Rust 版），参考 Kotlin `AgiHarnessAgent.kt` / Java `HarnessCodingAgent.java`，结合 ACP Rust SDK。

## 关键决策（ADR）
- 将 ACP CodingAgent 放在 `agentscope-harness` crate 的 `acp/` 模块，而非 core（依赖 ACP SDK 与 harness Filesystem，属于 harness 层）。
- 用 `role::acp::Agent`（服务端角色）builder + `on_receive_request!()` 宏注册 10 个 request handler。
- 会话取消用 `Arc<AtomicBool>` 轮询（50ms）而非 oneshot channel，以支持 `AcpAgentSession: Clone`（存入注册表需 Clone）。

## 踩坑/经验（Learnings）
- `agent-client-protocol-schema` 是独立 crates.io 依赖（v1.6.0），源码在 cargo registry：`C:\Users\Administrator\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\agent-client-protocol-schema-1.6.0\src\v1\`。
- `ProtocolVersion` 在 `schema::ProtocolVersion`（非 `schema::v1::`），是 u16 数值（1），不是 "2025-03-26" 字符串。
- `NewSessionRequest` 必须带 `mcpServers` 字段（反序列化要求）。
- `ChatUsage.total_tokens` 是方法非字段。
- `Usage` / `PromptResponse.usage` 需 `unstable_end_turn_token_usage` feature（未启用，故本轮不发送 usage）。
- `ToolResultBlock` 在 `agentscope_core::message` 而非 `tool`。
- 既有损坏示例 `examples/harness_agent.rs`（AgentSkillBuilder::new 等）导致 `cargo test -p agentscope-harness`（含 examples）失败，与本改动无关。

## 验证结果
- `cargo build -p agentscope-harness` / `-p agentscope-core` 通过。
- `cargo test -p agentscope-harness --lib`：135 通过（含 acp 7 新单测）。
- stdio 端到端：initialize / session/new / session/prompt（AgentMessageChunk 流式 + end_turn）/ session/close 全链路验证通过。
